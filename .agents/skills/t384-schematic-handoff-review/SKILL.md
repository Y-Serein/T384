# T384 原理图接手审核

## 目标

把一次原理图审核变成可复核、可交接的闭环：

`目标 → 状态 → 误差 → 控制动作 → 反馈 → 修正 → 验证 → 沉淀`

本 Skill 面向 T384 工作区的 T384/T640 方案，不把厂商参考工程、AX620Q/MIPI 方案、256×192 原型或 UVC 示例当作当前产品证据。

## 默认边界

- 默认只读审核；用户没有明确要求时不改原理图、PCB、固件、BOM、epro2 或原始附件。
- 用户明确不要求查看 epro2 时不要查看；只用最新导出 PDF，并明确因此无法验证源工程真实网表、ERC、PCB DRC 和布局。
- 需要更新交接时写项目根目录 `HANDOFF.md`；需要长期沉淀时写 `docs/runbooks/PROJECT_MEMORY.md`。不要默认写 QA_Log。
- 不联网下载或安装工具链/依赖；本地数据手册和项目资料优先。
- 没有真实硬件时必须写“未上板验证”，不能把静态审查写成产品完成。

## 需求基线

以项目 README、MINI2 接口表/指令表和用户已确认决策为准：

- 目标 SKU 是 T384/T640，暂不做 256×192。
- 产品链路是 `MINI2 → 8-bit DVP → CH32H417 V5F + DMA/缓存 → USB NCM → 本地 HTTP/Web`，不是 UVC，也不是 MIPI。
- MINI2 主电源是 5V±10%，启动探测器约有 500mA 浪涌；必须核对连接器处最坏电压和供电余量。
- DVP/I²C 默认 1.8V；UART、nRST 是 3.3V；`VDD_3V3_EXT` 是机芯电源，不要把它误认为 IO 电平配置。
- DVP 连接器命名 `DVP_DATA8..15` 对应模块 DATA0..7。必须按实际连接器 pin 核对，不按数字连续性猜线。
- UART 是 115200 8N1、无流控；模块的 UART0/UART1 名称是模块对端视角，不等于 CH32 的 USART 编号。
- MINI2 I²C 地址使用 7-bit `0x3C`；`0x78/0x79` 只是在协议资料中表示 8-bit 写/读地址。
- 测温表、RAW16、DVP采样沿、消隐、信息行、NCM持续吞吐和移动端兼容，除非已有硬件/日志证据，否则都标为待验证。

## 逐项审核方法

### 1. 连接器和物理 pin

建立“MINI2 pin → 模块信号 → 电压/方向 → 转换器 B/A 侧 → CH32 物理 pin/复用”的表。重点防止：

- 把连接器 pin 编号拼进网络名，例如把 `...PAO14` + CN1 pin6 看成 `...PAO146`；
- 把模块 `UART1_TX` 误认为 MCU `UART1_TX`；
- 只看同名而不看 TX→RX/RX→TX；
- 把 `DVP_DATA8..15` 当成 MCU DVP 位号；
- 把 MIPI、模块 USB 或未使用控制脚强行接入当前 DVP 方案。

### 2. CH32H417 复用和数据路径

对照官方数据手册确认 MCU 物理 pin 和 AF，不凭经验猜：

- 当前目标 DVP：`PC6..PC9` 对应 DVP_D0..D3，`PD12..PD15` 对应 DVP_D4..D7；控制脚通常核对 `PB12/PB13/PB14` 和可选 `PC12`。
- MINI2 UART1 当前若接 `PC10/PC11`，应明确它对应 CH32 `USART3_TX/RX`，不是 CH32 `USART1`。
- MINI2 UART0 当前若接 `PF4/PF3`，应明确它对应 CH32 `USART4_TX/RX`。
- I²C 主机当前核对 `PA13/PA14` 与 U7 两侧；I²C 从机当前核对 `PB10/PB11` 是否在同一默认 1.8V域。
- 核对 DVP_DATA12 是否只保留一条有效 MCU 数据路径。

### 3. 电平、默认状态和转换器

- SGM4553：A=CH32 `VIO_1.8`，B=MINI2 3.3V，VCCA≤VCCB，OE极性和默认状态正确；不要因为“自动双向”而交换电源。
- UART 必须通过电平转换且方向交叉；DVP/I²C 默认 1.8V 时不能直接让 CH32 3.3V 推入模块。
- `WORK_MODE` 未使用时让模块 pin 浮空，MCU 侧也不要驱动；如果要用，增加 3.3V有效电平的缓冲，不要用 1.8V GPIO硬推。
- `nRST` 未使用时可浮空；如果要控制，必须采用适合 3.3V低有效输入的开漏/三态方案。
- 用户已明确不使用的 `CAM_5V_EN` 不要再次当作缺陷；但要说明直供后失去软件断电/上电控制能力。

### 4. CH32 电源和 XO 配置

核对：

- `VDD33 ≥ VDD33A ≥ VDDIO ≥ VIO18`；`VDD12A/VDDK` 在约 1.17–1.27V范围；外部 3.3V和约1.23V的消费者是否正确。
- VIO18 的 XO 下拉配置。CH32H417 目标 1.8V时，不能保留约100kΩ XO 下拉；最新版本若已移除 R30，应标记旧问题已解决。
- 输入/输出电容、晶体负载、DC/DC 分压和电感电流额定值。只凭原理图不能替代布局和示波器验证。
- 重点检查 `VSYS` 到 MINI2 5V pin 的串联二极管/开关压降，按最低输入、500mA浪涌、温升评估，而不是只看标称 5V。

### 5. USB 和烧录

- USB-C 设备侧公头：CC1/CC2 各 5.1kΩ 下拉；A6/D+→USBHS_DP，A7/D−→USBHS_DM。
- 当前 USB2-only 时，SuperSpeed 可保持 NC；不要为了追求 USB3 随意补线。
- P2/U4 共享 D+/D−时，先应用用户已确认的“同一时刻只接一个接口、供电隔离”约束；只有在未来要求双口同时使用时才判定并口为功能问题。
- U4 若被用户定义为 USB 烧录/服务口，按物理连接接受其用途，但把 USB Boot/IAP 进入条件、恢复烧录和固件支持列为待验证；不要把 U4误写成 SWD。
- 若需求明确要求 WCH-Link/SWD，单独核对 PB8/PB9 的 SWCLK/SWDIO通路，不以 USB D+/D−替代 SWD。

## 闭环报告格式

输出时按以下顺序：

1. **目标**：列出本次采用的产品需求和文件版本。
2. **状态**：给出当前 PDF/源工程/硬件可见状态。
3. **误差**：先列合理项，再列问题；不要用大段“无问题”淹没风险。
4. **控制动作**：每个问题写具体修改或实测动作。
5. **反馈**：说明用户此前确认的边界，例如不看 epro2、单口使用、WORK_MODE/CAM_5V_EN不使用。
6. **修正**：区分本轮已修正、旧问题已解决、仍存在的问题；没有改文件时明确写未改动。
7. **验证**：列实际命令和结果，单独列未运行的 ERC/DRC、PCB、SPICE、固件、真机和上板验证。
8. **沉淀**：若用户要求，更新 HANDOFF 和 PROJECT_MEMORY；否则只在回复中给建议，不自动写记忆。

问题表至少使用三类：

- **P0/确定缺陷或重大电源风险**：可能导致不上电、接口失效或打板失败。
- **P1/应修正项**：标注错误、可靠性缺口或明确设计边界问题。
- **P2/待实测项**：静态原理图无法证明，必须靠源工程、PCB、固件或硬件验证。

结论必须回答：

- 信号互连是否符合需求；
- 是否有会导致首板失败的确定问题；
- 是否可以打样，哪些条件必须先满足；
- 哪些能力尚未由原理图证明。

## 30 秒 HANDOFF 要求

`HANDOFF.md` 顶部必须先写：

- 当前产品链路和目标 SKU；
- 当前审核对象的精确路径、时间和版本；
- 一句话结论；
- 当前 P0/P1/P2；
- 是否修改文件、是否上板；
- 下一次打开后的 3–5 个动作。

旧问题要放在“历史修正”中，不能继续放在“当前未决”里。特别注意 UART方向、PA14/pin6、R30、USB极性、WORK_MODE、CAM_5V_EN 和 U4/P2 单口约束。

## 典型错误防护

审核前后都检查这些反模式：

- 看到 `PC11` 就称为“UART1”，不确认实际是 `USART3_RX`；
- 看到 `PAO146` 就认定 SCL 断路，不确认最后的 6 是 CN1 pin编号；
- 继续引用旧 PDF/HANDOFF 的 R30、UART0、USB极性问题；
- 把用户已取消的 WORK_MODE、CAM_5V_EN 或已约束的 USB并口当作当前 P0；
- 只看 USB 480Mbps 标称值就宣称 640×512@50fps NCM完成；
- 把 U4 USB烧录口称作 SWD，或把存在 56KB BootLoader 区误写成 USB IAP已验证；
- 把 `VDD_3V3_EXT` 和 DVP/I²C 逻辑电平混为一谈；
- 只看 PDF 标签就声称真实网络已经连通；
- 把没有上板的静态结论写成电压、温升、枚举、丢帧或测温精度通过。
