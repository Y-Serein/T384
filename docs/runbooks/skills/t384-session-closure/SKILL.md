## 执行边界与状态

- 恢复先给一句话当前状态，再按用户本轮目标行动；“先这样吧”停止原任务，交接不含继续优化。
- 本项目当前合作边界是用户编译/测试/产物检查/烧录，代理日志和源码分析、最小可回滚修改及差异检查。**不要再设置“代理确认新map后才允许用户烧录”的流程。** 新授权可改变边界；不把以前代理运行过的检查当本轮授权。
- 以用户指定的工程可用目标收束。可以在完整性不受损时接受明确报告的整帧跳号，不把零丢帧、OEM、全温区或所有平台变成两点实验标定的默认门槛。用户延期的验证不自动执行。
- 每轮一个吞吐变量，不混重构；额度有限时缩小范围，不跳完整帧、CRC/校验和、物理地址和内存所有权验证。
- 地址、profile、PN/FW、双核工程和板上身份从当前源码及实机日志核对，不照搬旧 skill 的18.1、单核或等待到货状态。
- 区分源码候选修改、已目标构建、用户确认已烧录、实机行为验证；无法对应新诊断字段时说明版本证据不足。

## 依据症状选择路径

### 标定保存/温度

先读当前源码，画清“原始帧→采集→拟合→报告→上传提交→Flash回读→运行时加载→页面温度”的实际调用链。不要因为已有采集脚本或Flash后端就称整条流程完成。需要正式OEM时再进入原厂表/算法/逐帧状态闭环，别把它强加给已明确的实验两点目标。

1. 区分Picture/YUYV的8-bit亮度与真实16-bit输入；packed Picture无损不证明保存了热数据。先用完整物理帧、prefix和BE/LE ROI统计识别字节序，再归一化为既有wire。数据域不能仅靠命令值或API名字判断。
2. 资料冲突时同时保留来源。MINI2 V0.4表与AC020 SDK的0x45/85枚举不同；SDK明确有WN2/TIF系列的mid-mode接口。按完整class/index/长度、当前PN/FW与实测回读裁决，不把旧表KBC直接写成已证明NUC14。
3. 未验证的模式先做经用户确认的单变量探测：主循环发送命令、有限观测、保存原始证据、恢复已知模式并验证。ISR不发UART；已验证后才进入持续数据流。临时探测完成不等于全帧主机流或标定完成。
4. 黑体入口优先复用已有工具；当前640默认0/50、每点30帧，实际条件以用户为准。原始帧/状态/身份保存，允许报告unknown gain而不伪造成功；实验与OEM明确分开。默认采集不写入，显式--apply才写，先检查应用接口再要求用户操作黑体。
5. 保存前重算原帧数据、确认当前PN/SN/FW/规格、备份旧包；按实际擦除粒度区分A/B物理页。单模组设备共用一组A/B即可，勿默认按SKU分配多组。保持CRC、逐字节接收、读回与最后有效标记。规格/身份字段保留不代表已实现所有运行时状态绑定。
6. 读回比较全部持久header字段与payload，单独验证runtime_model_available和实际定点参数；动态applied字段不能导致假“标定被更改”。失去提交响应时状态未知，先只读verify-saved，不盲目重写。保存时cold_boot=false的快照不能否定用户后续已确认的现场验证，也不能编造验证细项。
7. 384兼容按地址/二进制格式/参数含义/已有入口核对，不仅看尺寸。v1的 `<HHIIi>` 保存点为非负整数；不要把分析支持负温/小数等同存储支持。页面允许新profile还需固件headers和模型加载同步，且Picture保持温度不可用。
8. 页面源、普通C include、gzip C include一起同步；使用现有embed工具明确source/output/gzip-output路径，检查解压正文和Content-Length。源码资源生成不等于固件构建、烧录或浏览器真机通过。

### USB 回归

先看用户的枚举/IP/HTTP证据并隔离最近一轮源码改动，避免叠加 PID/描述符/地址变动。CPU过载、跨核访问/对齐、内存区域和空闲路径计算属于候选原因；回滚后恢复也不自动证明唯一根因。不得回滚用户其他工作。协议或电平修改需相应证据和授权。

### 连接可用但无图/低 FPS

1. source：真实帧/行/字节增长、实际模式和输入格式、坏帧/溢出；只读确认 PN/FW，不按分辨率猜配置命令。
2. pipeline：物理存储与逻辑整帧容量、FRAME_START/END和偏移、abort/无槽/队列水位。字节增长但完整帧0时先检查半帧中止。
3. transport：HTTP完整帧/BPS、sendbuf耗尽或write ERR_MEM、NCM TX drop/backpressure，再考虑 COPY/校验/ACK/聚合成本。
4. browser：设备交付足够才定位解析/渲染；source60FPS不能代替网页完整帧率。

published可能包含空闲释放。停流瞬时速率归零，取活动期间有时间间隔的快照；要求用户浏览器操作时给当前完整网址。检查无损打包适用条件，色度变化必须明确拒绝，消费者租约内展开，COPY完成才释放；不得在空闲遍历中重复全像素计算。读取完整报告的errors/stable，成功的视频窗口与并行诊断错误分别报告。

### 内存与链接

- 先区分CodeFlash与SRAM；H417本项目资料为960KiB Flash、896KiB SRAM，不把数字加错。以实际核职责和占用回收空闲区，保留合理代码/堆/栈余量；不用一整帧静态缓存作为唯一可行架构。
- 分块队列是否够用取决于帧内积压与消费，不只平均FPS。小于一整帧时明确背压边界并验证完整END，不拼接不同物理帧冒充一帧。
- 新共享段要同步两核NOLOAD、slot mapper、真实地址探针、ABI版本、链接断言；不要让旧核仍拥有已回收区域。条件化分区应保留未使用该布局的旧profile路径。
- 链接脚本的字面地址在输出段内可能是相对值。绝对堆界限放段外并用ABSOLUTE，增加精确地址和完整代码尾界断言；不能只检查“链接成功”或静态字节总和。产物/下载由用户执行，不把静态分析升级为上板验收。
- 不凭ISR与主任务共存就报告所有getter有数据竞争。核对调用线程、是否重入及seqlock覆盖范围；HTTP和probe主任务同循环时，不把阻塞UART包进ISR序列锁。
